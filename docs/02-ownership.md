# 02. 소유권: 누가 값을 관리하는가

근거: [Book 4.1: Ownership](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html),
[Book 15.4: Rc](https://doc.rust-lang.org/book/ch15-04-rc.html).

## 기본 규칙

일반적인 소유 값에는 소유자가 있고, 소유권이 다른 바인딩이나 함수로 넘어갈 수 있습니다.
소유자가 유효 범위를 벗어나면 값이 정리됩니다. 이 규칙과 대여 검사를 컴파일러가 확인합니다.
값을 사용한 뒤 누가 정리하는지가 명확해져 중복 해제와 해제 후 사용 같은 문제를 막습니다.

`Rc`와 `Arc`를 통한 공유 소유권은 뒤에서 배웁니다. 지금은 `String`과 단일 소유권에 집중합니다.

## String을 대입하면

```rust
let original = String::from("Rust");
let moved = original;
// println!("{original}"); // 이동했으므로 사용할 수 없다.
println!("{moved}");
```

여기서 두 문자열 버퍼를 만든 것이 아닙니다. String의 소유권이 moved로 이전됩니다.
기존 바인딩을 계속 쓰면 컴파일러가 E0382로 거부합니다.
함수 인수가 `String`이고 호출할 때 넘겨주면 같은 방식으로 소유권이 이동합니다.

| 동작 | 원래 값을 계속 쓰나? | 의미 |
| --- | --- | --- |
| `let b = a;` (String) | 아니요 | 소유권 이동 |
| `let b = a;` (u32) | 예 | Copy 타입의 값 복사 |
| `let b = a.clone();` (String) | 예 | 별도 문자열 데이터 복제 |
| `let b = &a;` | 대여 규칙 안에서 예 | 소유권 없이 참조 |

정수가 복사되는 이유를 단순히 “스택에 있어서”라고 외우지 마세요. 타입이 `Copy`를 구현하는지가 기준입니다.
String은 Copy가 아니며, clone은 새 문자열 데이터 할당·복사가 필요할 수 있습니다.

## 메모리를 보는 방법

일반적인 지역 String은 포인터·길이·용량을 관리하고 문자열 데이터는 힙에 둡니다.
변수를 다른 곳으로 옮긴다고 버퍼 전체를 매번 복제하지는 않습니다.
구현 최적화까지 모든 값이 반드시 특정 위치에 존재한다고 일반화할 필요는 없습니다.

## 함수 설계에 적용하기

이 저장소의 `Task::new(title: String, ...)`은 제목을 내부에 보관하므로 소유권을 받습니다.
`task.title() -> &str`은 읽기만 하므로 문자열을 빌려줍니다.
새 독립 데이터가 정말 필요할 때 clone을 쓰고, 읽기 때문에 생긴 이동 오류라면 참조를 먼저 검토하세요.

```sh
cargo run --example 02_ownership
cargo test --doc
rustc --explain E0382
```

예제의 주석을 잠시 풀어 오류 위치와 “이동된 곳”을 확인하고 원복합니다. ex02는 받은 String을 복제 없이 반환합니다.
완료 기준: 대입·인수 전달·반환 시점마다 현재 소유자를 설명할 수 있습니다.
